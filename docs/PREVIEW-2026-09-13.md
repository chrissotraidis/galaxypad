# GalaxyPad 0.1.0 experimental preview

This is a public experimental preview, not a stable release or a verified
compatibility claim.

## Packages

- **GalaxyPad-iOS-iPadOS-0.1.0-preview.1.ipa**: one ARM64 app for iPhone and iPad,
  configured for iOS/iPadOS 16+. Build 13 host with the measured PGO game module.
  The archive is ad-hoc signed and has no personal provisioning profile. Sign it
  with your own Apple account and compatible provisioning before device installation.
  See [local signing and installation](INSTALL_IPAD.md). It is not TestFlight.
- **GalaxyPad-macOS-0.1.0-preview.1.zip**: separate ARM64 macOS app, configured
  for macOS 14+. An IPA is not a native macOS application package. The Mac archive
  is ad-hoc signed, not Developer ID signed or notarized.
- SHA-256 manifests identify package contents and their source revision.
  License notices and corresponding-source information accompany the packages.

Both applications include the ahead-of-time compiled game-code module. They do
not include a game image, extracted game assets, or user saves. Import your own
supported USA RMGE01 revision 0 image. The game code executes as ARM64 while the
Dolphin-derived runtime supplies Wii hardware behavior; interpreter fallbacks
remain, and iOS has no runtime PowerPC JIT.

For an existing installation, preserve the bundle identity and compatible signing
identity. Do not delete the existing app to resolve a signing mismatch: that can
remove its saves. These release archives do not change either connected device.

## What changed

The mobile host improves controller reconnection and queued pause-button handling,
restores input focus at gameplay lifecycle boundaries, and keeps the display awake
for controller-only play. The known game-side Wiimote auto-sleep setting is disabled
only for the exact supported executable under byte and register guards. Audio
interruption recovery checks session activation before clearing interruption state.

Touch settings expose optional controls and clarify pause/tilt behavior. Diagnostics
separate frame-event counts, input delivery, rendering work, and audio counters;
expensive audio scans remain opt-in. Unaccepted pointer and vertex performance
experiments are not part of the shipping runtime.

## Controller finding

During the build 13 iPad test, Universal Control acquired a strong system focus
lock and redirected controller input to SpringBoard while GalaxyPad still reported
local focus. Tapping the game directly on the iPad restored controller callbacks
and both input APIs without restarting the app or reconnecting the Xbox controller.
Mac pointer/keyboard sharing was then disabled. The owner reported responsive input
on the repeat pause/resume test; the idle duration was not measured.

If this specific symptom recurs while using Universal Control, tap the game on the
iPad and disconnect the Mac keyboard/mouse link for the comparison. This evidence
does not establish the cause of every previous controller interruption.

## Validation and limits

The exact build 13 mobile host matches the source-file hashes recorded at its
build. It was tested on the physical iPad. The connected iPhone 14 remains on build
7; the release's latest controller changes do not yet have equivalent iPhone
hardware acceptance. Packaging and compilation are not full gameplay acceptance.

The controller ownership, pause-event, audio interruption, guarded Wiimote policy,
and archive-audit checks pass. The general repository check reached an existing
experimental test that requires an absent ignored input,
`generated/thp-kernels-r198-exits/candidate.c`; the full suite is not green.

Heavy scenes still slow down on iPad. The owner's iPhone 14 report is approximately
32 FPS in the affected gameplay, so iPhone performance is a major unresolved issue.
Audio underruns, long-session stability, touch tracking and full-game coverage remain
open. The HUD reports engine frame events, not guaranteed display completions.

See [mobile investigation](IOS-IPHONE-PERFORMANCE-PASS2.md) for exact evidence and
[release readiness](RELEASE-READINESS.md) for the outstanding stable-release gates.
